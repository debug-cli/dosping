Quick Start

No cloning needed. The setup scripts detect they are outside the repo, auto-clone from GitHub, install dependencies, and launch.

Linux / macOS

curl -fsSL https://raw.githubusercontent.com/debug-cli/dosping/main/setup.sh | bash

Windows (PowerShell)

irm https://raw.githubusercontent.com/debug-cli/dosping/main/setup.bat -OutFile setup.bat; .\setup.bat

Ubuntu / Debian

sudo apt update && sudo apt install -y git python3 python3-pip python3-venv && curl -fsSL https://raw.githubusercontent.com/debug-cli/dosping/main/setup.sh | bash

Arch Linux

sudo pacman -Sy --noconfirm git python python-pip && curl -fsSL https://raw.githubusercontent.com/debug-cli/dosping/main/setup.sh | bash

Termux

pkg update -y && pkg install -y git python && curl -fsSL https://raw.githubusercontent.com/debug-cli/dosping/main/setup.sh | bash

Windows CMD

git clone https://github.com/debug-cli/dosping.git && cd dosping && setup.bat

What is DOSping

DOSping ( /duːz/ /pɪŋ/ ) is a terminal-based network stress testing tool. It opens hundreds of concurrent TCP connections to a target IP address while simultaneously monitoring whether the target is still responding. The interface shows three live panels side by side: the flood log, the connectivity monitor, and a real-time stats sidebar.

Built with Python, Textual, Rich, and asyncio. Runs on Windows, Linux, and macOS.

What makes it different

  • Live split-panel UI showing attack output and connectivity status simultaneously
  • Real-time stats: connections per second, success rate, bytes transferred, latency
  • Multi-tab sessions: run up to 4 tests against different targets at the same time
  • Command palette with 11 actions for controlling tests without memorizing shortcuts
  • Log export for post-test analysis
  • Session summary printed to terminal on exit

SplashScreen plays the matrix animation. Press any key to move on.

SessionScreen is the main workspace. Holds all tabs. Automatically opens SetupModal on first load.

SetupModal is a ModalScreen overlay. Returns config data to SessionScreen, which creates a new tab. Press Escape to cancel.

Splash Screen

The first thing you see on launch. A matrix-style character reveal sweeps left to right across the DOSping ASCII logo. Random characters from the glitch set (!@#$%^&*01█▓▒░╬╠╣╦╩╗) appear and resolve into the correct characters as the sweep passes.

Below the logo, a KITT scanner bar (bouncing glow, left and right) runs continuously. The animation runs at 25 fps. Press any key to advance.

How the animation works

  1. A reveal_col counter increments each frame (40ms)
  2. Characters to the left of reveal_col render in their final form
  3. Characters within 3 columns of the sweep render as random glitch characters (40% chance of real character, 60% random)
  4. Characters to the right render as dim random characters (18% visibility)
  5. Once reveal_col passes the end, the full Rich-markup logo replaces the animation

Setup Modal

A modal overlay (ModalScreen) that appears on top of the session screen. Dims the background. Contains three input fields and two buttons.

  • Enter moves to the next field
  • Enter on the last field (Bots) submits

Connectivity Panel (Center)

Real-time connectivity status from two independent monitors: ICMP ping and TCP port probes.

Log format

PrefixMeaning
[ICMP] ●Ping reply received (target responding)
[ICMP] ⚠Timeout or unreachable (ICMP may be blocked)
[TCP:80] ●Port open, connection accepted
[TCP:80] ✖Timeout or error
[TCP:80] ↩Connection refused (port closed, host reachable)

TCP probe lines include latency (ms) and a sequential probe number.

Why ICMP shows "timed out" but TCP shows "OPEN": Many servers block ICMP at the firewall while keeping TCP services running. If you see ICMP timeouts with TCP OPEN responses, the target is alive. TCP is the more reliable indicator.

Multi-Tab Sessions

TabbedContent widget with up to 4 simultaneous test tabs. Each tab is fully independent: its own Flooder, ping subprocess, TCP probe loop, stats timer, and log buffers.

Tab lifecycle

  1. Press Ctrl+N or use "New Test" from the palette
  2. SetupModal opens as an overlay
  3. Enter target, ports, bots. Submit.
  4. New TestTabPane created with a TestPanel inside
  5. Tab becomes active immediately
  6. Flood, ICMP, and TCP monitors start on mount

Tab labels

Show the target IP and primary port. Spinner animation (⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏) at 10 fps while running. Checkmark on completion.

  • Running: ⠹ 178.79.134.182:80
  • Complete: ✓ 178.79.134.182:80
  • Multiple ports: ⠹ 178.79.134.182 (80,443)

Closing tabs

Ctrl+W or "Close Tab" command. Stops the flooder, kills ping, stops stats timer, removes the pane.

Tab limit

Maximum 4. Warning notification if you try to open a 5th.

Background behavior

Inactive tabs keep running. TabbedContent hides panes via CSS but does not unmount them. Workers, subprocesses, and timers continue in all tabs simultaneously.

Internals

DOSPingCommandProvider extends Textual's Provider. search() uses self.matcher(query) for fuzzy matching. Each command yields a Hit with score, highlighted text, and async callback. Callbacks delegate to SessionScreen or TestPanel methods.

Flood Engine

Flooder class in flooder.py. No UI dependencies. Communicates through callbacks.

How it works

  1. run() creates asyncio.Semaphore(50)
  2. Schedules _attack() for each bot (0 to bots-1)
  3. Ports assigned round-robin: ports[i % len(ports)]
  4. asyncio.gather() runs all, gated by the semaphore

Single connection (_attack)

  1. Check stop flag
  2. Acquire semaphore (blocks at 50 concurrent)
  3. asyncio.open_connection(target, port) with 3s timeout
  4. Write 1024 random bytes
  5. Drain write buffer
  6. Close writer
  7. Increment successful + bytes_sent
  8. On exception: increment failed
  9. Record monotonic timestamp for rate calculation
  10. Fire on_progress(current, total)
  11. Every 25 connections: fire on_log()

Rate calculation

connections_per_sec(window=5.0) counts timestamps in the last 5 seconds, divides by window. Old timestamps pruned each call. Smooth rolling average.

Stopping

stop() sets _stopped. Each coroutine checks before semaphore acquisition and before connecting. Running connections finish normally. Flood drains in seconds.

ICMP Monitor

Async worker in TestPanel. Spawns system ping as a subprocess, streams stdout.

Platform commands

OSCommandBehavior
Windowsping -t <target>Continuous
Linux/macOSping <target>Continuous

Line classification

  • "reply from" or "bytes from" = success
  • "timed out" or "unreachable" = timeout (note: ICMP may be blocked)
  • "pinging" or "ping" = informational header
  • Everything else = muted

Toggle

Off: ping subprocess killed, loop sleeps. On: new subprocess starts automatically.

TCP Probe Monitor

Async worker alongside ICMP. Probes each target port every 2 seconds. 3-second timeout.

Results

ResultSymbolMeaning
OPEN●Connection accepted. Includes latency (ms).
TIMEOUT✖3s elapsed. Port may be filtered.
REFUSED↩RST received. Host reachable, port closed.
Error✖Other OS error.

vs. the flood

TCP probe is read-only: opens, closes, measures latency. No payload. The flood sends 1 KB per connection. They run on separate workers.

Toggle

Off: loop sleeps. No subprocess involved, so toggle is instant.

Troubleshooting

"ICMP timed out" but "TCP OPEN"

Normal. Many hosts block ICMP at the firewall. TCP probe is the accurate indicator.

All connections fail (100% miss rate)

  • Check if the target is reachable (ping from a normal terminal)
  • Verify the port is open (telnet or nmap)
  • ISP or firewall may be blocking outbound connections
  • Target rate limiting or IPS dropping connections

CSS error in stylesheet

DOSping uses f-string hex injection into CSS (not Theme.variables). Check color format is #rrggbb, no alpha, no rgb().

"Max 4 concurrent tests"

Close an existing tab with Ctrl+W first.

setup.sh: permission denied

Run with bash setup.sh explicitly, or chmod +x setup.sh && ./setup.sh.

Python not found

Install Python 3.12+ from python.org. Windows: check "Add to PATH". Linux: apt install python3 or pacman -S python.

Still stuck? Open an issue at github.com/debug-cli/dosping/issues with OS, Python version, and full error output.
